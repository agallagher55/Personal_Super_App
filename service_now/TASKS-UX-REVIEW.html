Executive recommendation

ServiceNow is the record. /tasks is the action layer.

The next iteration should not recreate ServiceNow's table. It should add a focused work queue, preserve source provenance, and turn the scratchpad into a low-friction daily log.

  1. What deserves attention today?
  2. What am I waiting on, and from whom?
  3. What changed since I last looked?

Recommendations

Eight opportunities

1Lead with a daily work queue

The ServiceNow screenshot is an inventory: 60 active records, mixed types, old opened dates, sparse due dates, and several states. Categories that start collapsed give every open item similar weight and still require remembering where today's work lives.

  • Build a default Today view from overdue/due today, manually pinned, in-progress, newly changed, and high-priority work.
  • Keep categories as the planning and archive view.
  • Make Today a personal flag; do not depend on ServiceNow due dates, which are often blank.

2Model waiting and follow-up

“Awaiting User Info” is visible in ServiceNow, but pending and unknown source states currently flatten to open. That mixes blocked work into the actionable queue.

  • Map waiting states to the existing personal pending status or introduce waiting.
  • Add optional waiting_on and follow_up_date fields.
  • Provide a dedicated Waiting / follow-up lane.

3Expose ServiceNow provenance

Make ticket numbers direct links to the source record. In task detail, separate From ServiceNow read-only fields from editable My plan fields so it is clear what a future sync can overwrite.

From ServiceNow: number, source state, group, requester, description, opened date, and source update time.
My plan: priority, Today, estimate, tags, local override, checklist, files, and personal notes.

4Show synchronization health

Display the last successful run, active count, changed count, and any error. Store start/end time, result, counts, query fingerprint, and error text for each run.

ServiceNow · synced 14 min ago · 60 active · 3 changed · Sync now

Also reconcile absent source records. Mark them source_missing after a successful sync and require confirmation before archiving; never delete their personal notes.

5Turn the scratchpad into a dated daily log

“Today's List” currently points at one timeless text blob, so yesterday's contents can appear below today's date. Store one entry per local calendar date and open today's entry by default.

  • Add previous/next-day navigation.
  • Add a manual “Carry unfinished lines forward” action.
  • Convert a selected line into a personal task while preserving the original.
  • Keep plain text and autosave; also save on blur/page hide to protect the final keystrokes.

6Add source-aware facets and sorting

Use URL-backed, combinable filters for Today/overdue/no date, status, personal priority, ticket prefix, assignment group, no-ticket items, and changes since sync. Add sorting by personal order, due date, source update, oldest opened, and priority.

7Remove save ambiguity

The same screen currently mixes autosaved scratchpad text, explicitly saved task edits, and immediately persisted deletion.

  • Show a clear Saved / Unsaved task changes state.
  • Disable Save Changes until something changes.
  • Warn before leaving with unsaved edits.
  • Use optimistic concurrency so sync cannot silently overwrite an open editor.
  • Offer keyboard-accessible move controls rather than drag-and-drop alone.

8Improve scale and hierarchy

Lazy-render collapsed sections and paginate or virtualize completed history. On active cards, prioritize personal Today/priority, ticket and description, status/due/follow-up/age, then assignment and requester metadata.

Use text as well as color, and use semantic buttons with aria-expanded for every collapsible header.

Roadmap

Delivery plan

Phase 1 · Highest value

Trust and triage

  1. Map Awaiting User Info to pending/waiting.
  2. Add source opened/updated/last-seen fields and sync-run metadata.
  3. Link ticket numbers to ServiceNow.
  4. Add Today and follow-up dates; make Today the default Work view.
  5. Add dirty-state protection and accessible collapse controls.
Phase 2

Durable daily workflow

  1. Make scratchpad entries date-keyed.
  2. Add day navigation, carry-forward, and line-to-task conversion.
  3. Add URL-backed facets and sorting.
  4. Reconcile records absent from successful syncs.
Phase 3

Polish and automation

  1. Add a protected server-triggered sync or scheduled job.
  2. Add conflict/version handling.
  3. Lazy-render large sections and paginate completed history.
  4. Add a weekly review for completed, carried-over, stale, and waiting work.
Scope control

Deliberate non-goals

  • Do not reproduce every ServiceNow column or build another generic table.
  • Do not push personal notes, priority, or daily planning data back by default.
  • Do not automatically delete local tasks when a source record disappears.
  • Do not turn the scratchpad into a second structured task manager.
  • Do not add notifications before follow-up dates and source freshness are trustworthy.
