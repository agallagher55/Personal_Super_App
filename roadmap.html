Roadmap

A soft, living plan — priorities and rough sequencing, not a committed schedule. Revisit whenever priorities shift.

Last written 2026-09-04 · source docs: architecture_Review.md, finance/ARCHITECTURE.md, fitness/README.md, fitness/VISITOR-SIGNIN-PLAN.md, DATABASE-MIGRATION.md

Where things stand

Tasks tracker Done
Full CRUD, categories, tags, notes — the one feature that's been end-to-end real since the start.
Fitness / Google data pull Done
The app pulling one person's Google Health data (steps, HRV, SpO2, sleep, weight) via OAuth is fully working — this is the Fitbit replacement, since Fitbit's own Web API is being retired Sept 2026.
Fitness / visitor Google login Done
Any allowed visitor now signs in with their own Google account at /fitness/login and sees only their own data — browser-driven OAuth, signed session cookies, and per-user token/data storage under data/fitness/users/<user_id>/. See fitness/VISITOR-SIGNIN-PLAN.md.
Finance dashboard Planned, not built
UI is real but reads a static seed JSON file. Plaid sync layer is fully spec'd in finance/ARCHITECTURE.md but zero code exists yet.
Real database Tasks done, finance pending
Tasks moved off flat JSON onto SQLite: data/tasks.db with sections/tasks/tags tables, a generated done column that can't drift from status, and transactional writes. See DATABASE-MIGRATION.md. Finance still reads a static seed file; finance/schema.sql already defines its schema and standing it up is step one of the Plaid work below. Fitness stays on JSON deliberately (fitness/ARCHITECTURE.md §6).

Recommendation

Fitness visitor sign-in and the tasks database are both done. What's left of the database question folds into the finance work below: Phase 1 of the finance plan is literally "create data/finance.db from schema.sql," and it can now copy the pattern backend/tasks_db.py proved out.

Start with Finance: Link + storage. A free Plaid sandbox account, this repo's first third-party dependencies (plaid-python, cryptography), and an end-to-end Link flow against sandbox data — no real bank credentials or auth gate needed yet, since sandbox data isn't real money. See the "Up next" phase below for the concrete checklist, and note that the minimal auth gate has to land before anything later touches real transactions or flips PLAID_ENV to production.

Soft sequencing

Done

Fitness: per-visitor Google sign-in

  • Browser-driven OAuth: /fitness/login → /fitness/auth/start → consent screen → /fitness/auth/callback in backend/server.py — adapted from the CLI-only flow in backend/fitness/auth.py
  • A signed-cookie session layer (backend/fitness/session.py) — stateless, no server-side session store
  • Per-user token storage (data/fitness/users/<user_id>/tokens.json), replacing the single backend/fitness/config.json
  • Per-user data storage (data/fitness/users/<user_id>/health_data.json), replacing the single data/fitness/health_data.json
  • Each expected visitor's email still needs adding to the OAuth client's Test users list in Google Cloud Console (manual, outside code, required today per the cap above), plus one of FITNESS_OWNER_EMAIL/FITNESS_ALLOWED_EMAILS/data/fitness/allowed_users.json set as this app's own allowlist
Up next

Finance: Link + storage

  • Plaid developer account, sandbox access (instant, free)
  • requirements.txt: plaid-python, cryptography — first third-party deps in the repo
  • data/finance.db from finance/schema.sql, plus db.py, crypto.py, plaid_client.py
  • Link flow end-to-end in Sandbox: one plaid_items row + its accounts rows
Later

Finance: transactions, and the fixes it now needs

  • /transactions/sync integration, real transaction list on /finance
  • Atomic writes + a file lock around JSON read-modify-write (cheap, closes a data-loss risk that gets worse once real bank data is involved)
  • Pull the minimal auth gate forward from Phase 5 (a public URL holding real transactions needs this sooner than "eventually")
Further out

Finance: investments, categorization, going live

  • Holdings + investment transactions, net-worth/portfolio summary
  • User-editable transaction categories, spending-by-category view
  • Harden the auth gate, then flip PLAID_ENV from sandbox to production
Watch list

Not urgent, but resurface before it gets expensive

  • Flask/Django migration decision (cheap to defer now, expensive to defer once finance route code piles up on stdlib http.server)
  • Basic test suite for backend/server.py's handlers (the storage layer now has one, backend/tests/test_tasks_db.py; the request handlers themselves still don't)
  • Shared static/js/api.js module to stop the 4-way duplication across tasks pages
  • Nightly scheduled Plaid sync, liabilities product, holdings-history table (finance Phase 6, optional)
  • Fitness OAuth client verification in Google Cloud Console (removes the 7-day refresh-token expiry and 100-user Test users cap — the single biggest thing making sign-in feel unfinished past family/friends scale, see fitness/google_health.md §9)
  • Scheduled fitness sync for every visitor (cli.py sync --all on a cron) (today, a visitor's data only refreshes on first sign-in or a manual Sync now click)
