Roadmap

A soft, living plan — priorities and rough sequencing, not a committed schedule. Revisit whenever priorities shift.

Where things stand

Tasks tracker Done2026-09-10▸
Full CRUD, categories, tags, notes — the one feature that's been end-to-end real since the start. It also pulls the "My Work" list out of Halifax's ServiceNow GIS dashboard (service_now/sync.py, a CLI script matched on sys_id so re-runs never duplicate a task or overwrite a note you typed), and layers a personal triage pass on top that ServiceNow never sees: Today / Waiting / Overdue queue pills, a per-task Today flag, and a follow-up date for blocked work. Every sync attempt is logged, so the page can say how fresh its ServiceNow data is and flag what changed upstream since you last looked. service_now/TASKS-UX-REVIEW.md is the review of that whole workflow; what's left of it is tracked in issue #160.
Fitness / Google data pull Done2026-08-27▸
The app pulling one person's Google Health data (steps, HRV, SpO2, sleep, weight) via OAuth is fully working — this is the Fitbit replacement, since Fitbit's own Web API is being retired Sept 2026.
Fitness / visitor Google login Done2026-09-02▸
Any allowed visitor now signs in with their own Google account at /fitness/login and sees only their own data — browser-driven OAuth, signed session cookies, and per-user token/data storage under data/fitness/users/<user_id>/. See fitness/VISITOR-SIGNIN-PLAN.md.
Finance: Spending & Cash Flow Done2026-09-07▸
Real data, not a sample file: a manual CSV import (credit card + bank activity exports, decided instead of Plaid for now) loads into data/finance/finance.db, driving a category donut, top merchants, a monthly spend chart, editable categories, and a Cash Flow block (income/expense trend, click a bar for that month's transactions, a per-type income breakdown, per-transaction exclusions). See finance/ARCHITECTURE.md Part A.
Finance: net worth Partly built
Cash, Bitcoin, Debt, and Lines of Credit now have real, dated balance history (account_balance_snapshots etc.) and a manual-entry route, seeded from the old sample values — finance/ARCHITECTURE.md Part C, Phase 1. /finance itself hasn't been switched over yet, so those sections (plus Investments and Net Worth Over Time) still render the old static finance-dashboard.json.
Real database Done2026-09-06▸
Tasks moved off flat JSON onto SQLite: data/tasks.db with sections/tasks/tags tables, a generated done column that can't drift from status, and transactional writes. backend/tasks_export.py regenerates the committed JSON snapshot from it. See DATABASE-MIGRATION.md. Finance ended up with its own SQLite store too (backend/finance/, data/finance/finance.db) — built around CSV import rather than finance/schema.sql's original Plaid-oriented design, which stays unused; see finance/ARCHITECTURE.md Part A1. Fitness stays on JSON deliberately (fitness/ARCHITECTURE.md §6).
One design system Done2026-09-08▸
Every section now shares one palette, type scale and set of components, in both light and dark. /fitness had carried the ported personal_health project's own slate/blue look, system-ui type and opposite-corner theme toggle, so it read as a different product next to /finance; it now loads static/styles/styles.css like every other page, with fitness-only components layered on top. Its charts take theme tokens instead of hex, so they follow the toggle. Every page also finally declares a viewport meta, without which none of the mobile breakpoints ever fired. See DESIGN-SYSTEM.md.

Recommendation

Fitness visitor sign-in, the tasks database, and Finance's Spending/Cash Flow sections are all done. Finance's net worth side just got its own real tables (Part C Phase 1) but the dashboard hasn't been pointed at them yet.

Continue Part C: investment holdings (Phase 2), then cut the net worth dashboard over to real data (Phase 3). Investments is the one net-worth section still missing its own tables (securities/investment_holdings_snapshots) — landing those lets Cash/Investments/Bitcoin/Debt/Lines of Credit/Net Worth Over Time all switch off the static sample JSON in one cutover instead of half-migrating the page. See finance/ARCHITECTURE.md Part C, §C10 for the full phased plan.

Soft sequencing

Done▸ 2026-09-02

Fitness: per-visitor Google sign-in
  • Browser-driven OAuth: /fitness/login → /fitness/auth/start → consent screen → /fitness/auth/callback in backend/server.py — adapted from the CLI-only flow in backend/fitness/auth.py
  • A signed-cookie session layer (backend/fitness/session.py) — stateless, no server-side session store
  • Per-user token storage (data/fitness/users/<user_id>/tokens.json), replacing the single backend/fitness/config.json
  • Per-user data storage (data/fitness/users/<user_id>/health_data.json), replacing the single data/fitness/health_data.json
  • Each expected visitor's email still needs adding to the OAuth client's Test users list in Google Cloud Console (manual, outside code, required today per the cap above), plus one of FITNESS_OWNER_EMAIL/FITNESS_ALLOWED_EMAILS/data/fitness/allowed_users.json set as this app's own allowlist
Done▸ 2026-09-07

Finance: CSV-import pipeline, and its first real net worth tables
  • Decided against Plaid for now (no developer account, no production-approval process, no auth gate needed yet) — manual CSV export from the credit card and bank sites instead, into backend/finance/ + data/finance/finance.db. See finance/ARCHITECTURE.md Part A.
  • Spending (category donut, click-to-filter top merchants, monthly chart, one-time/permanent category fixes) and Cash Flow (income/expense trend, click a bar for its transactions, per-row exclusions, a per-type income breakdown) — both reading real imported data
  • Transaction ids moved from file position to content-derived hashes, fixing a live bug where a re-import could silently move a category correction or Cash Flow exclusion onto the wrong transaction (finance/ARCHITECTURE.md §A3b)
  • Part C Phase 1: real, dated balance history for Cash/Bitcoin/Debt/Lines of Credit (account_balance_snapshots, account_terms_snapshots), a manual-entry route (POST /finance/balance-entries), seeded from the old sample values
Up next

Finance: investment holdings (Part C, Phase 2)

  • securities + investment_holdings_snapshots tables, POST /finance/holding-entries
  • Seed today's TFSA/RRSP/FHSA/Non-Registered holdings from the sample JSON, same as Phase 1 did for Cash/Bitcoin/Debt/Lines of Credit
Later

Finance: cut the net worth dashboard over, and the second credit card

  • Part C Phase 3: point Cash/Investments/Bitcoin/Debt/Lines of Credit/Net Worth Over Time at the real tables instead of finance-dashboard.json; retire that file (the visible payoff of Phases 1-2 — deliberately sequenced after Investments so every section moves at once)
  • A second credit card, from a different institution (documented in finance/ARCHITECTURE.md §A9 — blocked on a real sample export to design a parser against, not on a decision)
Later

Tasks: make the ServiceNow layer trustworthy

  • Sync health is done (2026-09-10): each task now records when its ticket was opened and last changed upstream, every sync attempt is logged to sync_runs whether it succeeded or failed, and /tasks shows how fresh the data is (schema migration 5, /tasks/sync-status.json)
  • Rest of Phase 1: persistent saved/unsaved state for task edits, and real button semantics on the collapsible sections (they're divs with click handlers today, so none of them are keyboard reachable)
  • Then Phase 2: date the scratchpad so yesterday's list stops being presented as today's, reconcile tickets that drop out of the active query without ever deleting their notes, and add real queue facets
  • Full plan and per-item scope in issue #160; the review itself is service_now/TASKS-UX-REVIEW.md
Further out

Finance: raw/staging layer under CSV transactions, then an auth gate

  • Part C Phase 4: raw_credit_card_transactions/raw_bank_activity plus the replay rule, so a parsing fix can be replayed over all history instead of only affecting new imports; backfill today's already-imported CSVs into it
  • A real auth gate in front of the upload/route endpoints (still just the same-origin check from Part A4 — fine for a single-user personal tool today, but the actual prerequisite before Plaid/Part B could ever be revisited)
Watch list

  • Basic test suite for backend/server.py's handlers (the storage layers all have one now — backend/tests/test_tasks_db.py, backend/finance/tests/; the request handlers themselves still don't)
  • Shared static/js/api.js module to stop the 4-way duplication across tasks pages
  • Plaid-based live sync (kept in full as Part B of finance/ARCHITECTURE.md, fully deferred rather than dropped — revisit only if CSV import + manual entry stops being enough)

  • Scheduled fitness sync for every visitor (cli.py sync --all on a cron) (today, a visitor's data only refreshes on first sign-in or a manual Sync now click)
